# Maintenance Rules

Installed request files carry the provenance header defined in
`code_generation_rules.md`, linking each one back to its source Postman
collection and request. Use these rules to keep them current.

## Listing installed requests

Search the project for files containing "Generated by Postman Code" in a
comment within the first 15 lines. Parse each file's header for collection
name, collection UID, request path, request UID, and modified-at
timestamp. Present a table: local file path (relative to project root),
collection name, request path, last-modified timestamp.

## Checking for updates

Scan for installed requests as above. For each one, call
`getRequestContext` to fetch the current request's updated-at timestamp
and compare it to the `Request modified at` value in the file header.
Report a table of every installed request with its status
(current/outdated). For outdated ones, ask before regenerating — on
confirmation, call `getRequestCodeContext` to re-fetch context and
regenerate the file in place, matching its existing code style and
updating the header timestamp.

## Finding unused requests

Scan for installed requests, then for each one search the rest of the
project for imports, requires, or other references to it (by module path,
relative path, or exported function name). Report requests with zero
references. Offer removal — on confirmation, delete the file and remove
any now-empty parent directories up the tree.

## Removing an installed request

Identify the file by path, request name, or request UID (list installed
requests first and ask if ambiguous). Then:

1. Delete the request file.
2. Remove empty parent directories up the tree, stopping at the first one
   with remaining contents.
3. Search the project for imports/requires referencing the deleted file
   and warn about any broken references so the user can update them.
